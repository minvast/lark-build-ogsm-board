# 飞书 Aily 部署说明

## 推荐架构

把本 Skill 适配为“两层”而不是一个超长提示词：

1. **Aily Agent Skill**：理解用户意图、读取当前会话中的文字与文件、解释预检、每次只问一个决策问题，并选择下一项操作。
2. **工作流或自定义连接器后端**：完成标准化、分页读取、人员查询、Base 写入、幂等回读和审计。写入后端是最终安全边界，不能只相信模型传来的“用户已同意”。

OGSM 搭建属于多步骤且要求稳定结果的任务。Agent Skill 保留对话弹性，复杂执行封装为五个粗粒度操作；不要把每个飞书 OpenAPI 都暴露给 Agent。仓库和通用 ZIP 也不是可直接导入的 Aily 应用包。

## 在 Aily 中配置

1. 在 Aily 开发工作台进入“技能编排”，新增一个 Agent Skill。
2. 将 [agent-skill-prompt.md](agent-skill-prompt.md) 中代码块内的正文粘贴到提示词区域。
3. 添加 [operation-contracts.md](operation-contracts.md) 定义的五个操作，名称保持完全一致。Aily 当前每个 Agent Skill 最多添加 8 个操作、建议不超过 5 个，单次触发最多执行 10 次操作；本适配器固定为 5 个粗粒度操作，并让每个操作支持批量部门。
4. 使用操作描述写清调用意图、输入来源和示例。复杂逻辑用工作流实现；若使用自定义连接器，一个 HTTP 操作只负责调用一个稳定的后端接口。
5. 配置输入字段：
   - `source`、`scope`、`topology_hint`、`names` 等用户意图字段可设为 AI 推断，并提供中文示例。
   - `source_fingerprint`、`normalized_ref`、`plan_id`、`snapshot_id`、`operation_log_id` 必须从上一步输出原样传递，字段描述明确写“不可生成、改写或概括”。
   - `approved` 只能依据用户对当前计划摘要的最新明确回复判断；不得预设为 `true`。后端仍需核验确认摘要、计划版本、执行人和目标快照。
6. 只把模型决策所需的摘要字段设为“AI 处理”：状态、问题、待确认项、不透明 ID、数量、链接和下一步。规范数据全集、原始 API 响应和详细日志留在后端，以引用 ID 传递，减少上下文噪声。
7. 在提示词中保留明确的操作顺序和输出传参规则。无歧义时通常执行 5 次，有决策项时通常执行 6 次，把剩余次数留给异常回读；不要为每个部门分别调用，也不要并行写入。
8. 使用调试控制台检查真实的操作顺序、AI 推断输入和返回字段。确认没有模型编造 ID、越过确认门或在超时后重复写入。
9. 发布前检查 Aily 计算出的连接器权限；只保留来源读取、必要通讯录查询和指定 Base 管理权限。每次变更操作或字段后重新调试并发布。

## Aily 上下文映射

- 适配器中约定：用户本轮文本映射为 `query`，附件或会话文件映射为 `source.files`，飞书表格/Base 链接映射为 `source.urls`。
- 当前用户 OpenID 只用于绑定计划执行人和权限审计；用户 `@` 的成员 OpenID 只作为人员解析候选，不等于唯一匹配结论。
- 会话中没有文件、链接或明确目标时，Agent 只询问缺失的那一项，不调用写操作。
- 多部门来源在一次 `inspect_ogsm_source` 中批量预检；收集完“独立还是合并”等答案后，用同一个 `normalized_ref` 复检并生成新的固定计划，不沿用预检草案。

## 后端必须实现的安全边界

- 为每次预检持久化 `source_fingerprint`、`normalized_ref`、`plan_id`、执行人 OpenID、计划摘要和有效期。
- 写入前比较最新 `snapshot_id`，并重新检查空键、重复键、计划外记录和权限。任一变化都让旧计划失效。
- `execute_approved_ogsm_plan` 必须检查 `approved=true`、确认摘要与固定计划一致，并拒绝过期、跨用户或跨会话计划。
- 超时、限流或响应不明时不盲目重试写操作；先读取操作日志和目标 Base，再决定是否继续。
- 删除接口与普通 upsert 分离。只有固定 record ID 清单、明确删除授权和执行前二次在线校验同时满足时才允许删除。
- 访问令牌、完整人员目录、原始业务数据和敏感凭证不得进入模型提示词或操作日志。

## 调试用例

至少逐条验证以下场景：

1. 来源含两个部门：Agent 先询问独立还是合并，不自行建 Base。
2. 负责人同名或找不到：人员字段保持空，Agent 不猜人。
3. 策略覆盖多个衡量项：Agent 等用户确认后才拆分，并保留原文。
4. 用户只说“继续”：当前计划摘要已经变化时不能沿用旧确认。
5. 目标已有空键、重复键或分页未读完：写操作被拒绝。
6. 写操作超时：Agent 先调用验收/回读，不直接再次执行。
7. 相同计划运行两次：第二次新增记录为 0。
8. 用户同意启用提醒但未指定接收人：工作流仍保持关闭。
9. 缺少完整 Base 回读能力：最终明确说明“尚未写入飞书多维表”。

## 上线验收

- 五个操作都返回统一结构化结果，字段说明足以让模型稳定传参。
- 未确认、确认已过期或目标发生变化时，后端拒绝写入。
- 相同计划重复运行不新增记录；工作流默认关闭。
- Agent 最终只展示业务结果和未解决事项，不主动展示指纹、计划 ID、快照 ID 或 record ID。
