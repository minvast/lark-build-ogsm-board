# 飞书 Aily 部署说明

## 推荐架构

使用一个 Agent Skill 承担对话、预检解释和人工确认；使用一个工作流或自定义连接器承担确定性的读取、写入和验收。不要把整个仓库 ZIP 当作 Aily 可直接导入包。

## 配置步骤

1. 在飞书 Aily 开发工作台创建智能体应用，并新建一个 Agent Skill。
2. 将 `agent-skill-prompt.md` 正文粘贴到 Agent Skill 提示词。
3. 添加 `operation-contracts.md` 定义的五个操作，名称保持完全一致。
4. 将五个操作绑定到工作流或自定义连接器。后端可调用飞书电子表格、通讯录和多维表格 OpenAPI，也可调用承载本仓库脚本逻辑的内部服务。
5. 在后端持久化 `source_fingerprint`、`plan_id`、`snapshot_id`、确认摘要和操作日志；写操作再次校验这些值。
6. 使用一份含歧义负责人、过宽策略和重复源记录 ID 的测试数据验证阻断行为，再用正常样例验证第二次 upsert 新增为 0。
7. 发布技能和应用。技能更新后重新验证操作绑定和权限范围。

## 权限与数据

- 只申请读取来源、查询必要通讯录字段、管理指定 Base 所需的最小权限。
- 执行身份必须能访问用户指定的数据源和目标 Base；无权限时返回明确错误，不得换目标重建。
- 若通过内部服务运行 Python 脚本，上传文件、规范数据和操作日志应设置保留期限，不把访问令牌写入日志。
- 删除重复记录建议单独暴露受限工作流节点，要求固定 record ID 清单和二次在线校验。

## 上线验收

- 未确认时调用写操作会被后端拒绝。
- 来源或目标在确认后变化时，旧计划会失效并回到预检。
- 歧义人员不会被自动写入。
- 工作流创建后为关闭状态。
- 相同数据重复运行不会新增记录。
- 没有完整回读能力时，Agent 明确只提供计划而不宣称完成。
